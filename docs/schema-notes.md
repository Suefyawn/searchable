# Schema notes: Postgres to D1 (SQLite)

Written for the Cloudflare migration (ADR-45). Every translation the Drizzle schema, the migrations and the raw SQL went through, in one place, so a query that looks odd has its reason here. The table map itself stays in `docs/DATABASE.md`.

## Types

| Postgres (before) | SQLite / D1 (after) | Helper in `src/db/schema/_shared.ts` | Notes |
|---|---|---|---|
| `pgEnum` (13 enums) | `text` with a `CHECK (col IN (...))` | `textEnum`, `enumColumn`, `enumCheckSql` | `x.enumValues` keeps working at every call site. Adding a value is a migration that rewrites the check. |
| `jsonb` (28 columns) | `text` in JSON mode | `json(name).$type<T>()` | Drizzle parses and serialises. SQL reads use `json_extract(col, '$.key')`. Defaults `'{}'` and `'[]'`. |
| `timestamp with time zone` | `integer` milliseconds since the epoch | `timestampMs`, `createdAt`, `updatedAt`, `nowMs` | Drizzle hands out `Date` objects as before. Raw SQL compares numbers: `created_at > ${date}` works because `rawQuery()` turns `Date` parameters into milliseconds. SQL now: `cast(unixepoch('subsec') * 1000 as integer)`. |
| `date` (`data_points.date`) | `text` ISO `YYYY-MM-DD` | none | Already compared and sorted as strings. |
| `double precision` | `real` | none | |
| `boolean` | `integer` 0/1 | `bool` | Drizzle maps to `boolean`. Raw SQL writes `1`/`0`. |
| `text` PK with `crypto.randomUUID()` | same | `id()` | |
| generated `tsvector` columns + GIN | dropped | none | Full-text search is an FTS5 virtual table, see below. |
| `pg_trgm` indexes | dropped | none | Fuzzy matching uses an FTS5 trigram table, see below. |
| composite PK, unique index, self FK | same | none | `AnyPgColumn` became `AnySQLiteColumn`. |

## Migrations

`drizzle/` (Postgres, 14 files) is retired with Vercel. D1 migrations live in `migrations/`, generated by `npm run db:generate` (drizzle-kit, sqlite dialect) and applied by `wrangler d1 migrations apply` (`npm run db:migrate` locally, `db:migrate:staging`, `db:migrate:production`). Wrangler records applied files in `d1_migrations`. Hand-written SQL that Drizzle cannot express (the FTS tables and their triggers) is its own numbered file in the same folder.

## Full-text search

`search_documents` keeps every column except the two generated vectors. Beside it:

- `search_fts`: `CREATE VIRTUAL TABLE search_fts USING fts5(title, keywords, summary, category, city, body, content='search_documents', content_rowid='rowid', tokenize='porter unicode61')`. External-content table, so the text is stored once. Three triggers keep it in step with inserts, updates and deletes on `search_documents`.
- `search_trgm`: `fts5(title, keywords, content='search_documents', content_rowid='rowid', tokenize='trigram')` for typo tolerance (`similarity()` and `%` before). If D1 ever lacks the trigram tokenizer the migration fails loudly and `search()` falls back to `LIKE` on the first three characters.
- Ranking: `bm25(search_fts, 10, 10, 4, 4, 4, 1)` mirrors the A/A/B/B/B/C weights the tsvector had, multiplied by the same boost, intent, popularity and freshness terms as before (`docs/SEARCH.md`).
- Query syntax: `websearch_to_tsquery` becomes an FTS5 match string built by `toFtsQuery()`: quoted phrases pass through, `OR` stays, `-word` becomes `NOT word`, remaining words are ANDed and the last one gets a `*` prefix so "electri" still finds electricity (this replaces `tsv_simple`).
- Snippets: `snippet(search_fts, -1, '<mark>', '</mark>', '…', 28)` replaces `ts_headline`; the text is escaped first as before.

## Raw SQL rewrites (115 sites)

| Before | After |
|---|---|
| `count(*)::int`, `::int`, `::float`, `::text` | cast dropped; SQLite is dynamically typed and D1 returns numbers as numbers |
| `now() - interval 'N days'` | `${Date.now() - N * 86_400_000}` computed in JS, or `unixepoch('now', '-N days') * 1000` |
| `props->>'k'` | `json_extract(props, '$.k')` |
| `jsonb_array_elements_text(topics)` in FROM | `json_each(topics)` |
| `value \|\| excluded.value` (jsonb merge) | `json_patch(value, excluded.value)` |
| `count(*) filter (where c)` | `sum(case when c then 1 else 0 end)` |
| `date_trunc('day', ts)::date` | `date(ts / 1000, 'unixepoch')` |
| `ILIKE` and drizzle `ilike()` | `LIKE` / `like()` (SQLite LIKE ignores ASCII case) |
| `greatest(a, b)`, `least(a, b)` | `max(a, b)`, `min(a, b)` (scalar forms) |
| `extract(epoch from now() - ts)` | `(${Date.now()} - ts) / 1000` |
| `with d as (delete ... returning 1) select count(*)` | plain `delete`, count read from `changes` via `rawRun()` |
| `regexp_replace(phone, '\D', '', 'g')` | phone normalised in JS before the query |
| `string_to_array(a) && string_to_array(b)` | word overlap computed in JS over the candidate rows |
| `pg_size_pretty(pg_database_size(...))` | `page_count * page_size` from `PRAGMA` |
| `row_number() over (...)`, `count(*) over ()` | unchanged (SQLite has window functions) |
| `on conflict ... do update ... where ... returning` | unchanged (SQLite 3.35+) |
| `nulls last` / `nulls first` | unchanged |
| `true` / `false` literals in SQL | `1` / `0` |

## Client

`src/db/index.ts` makes one Drizzle instance per isolate over the `DB` binding; there is no connection to pool or close. `rawQuery()` returns rows, `rawRun()` returns the change count. Scripts that touched the database directly (`seed.ts`, `reindex.ts`) now call the admin API of a running instance instead; `scripts/export-for-d1.ts` is the one script that opens Postgres, for the content migration.
